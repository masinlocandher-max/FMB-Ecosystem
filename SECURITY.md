# Security Policy

## Supported code

Security fixes are prepared against the default `main` branch through pull requests. Production deployments should only use reviewed commits from `main`.

## Report a vulnerability privately

Please do not open a public GitHub issue for a suspected vulnerability.

Email **withlovefmb@gmail.com** with:

- the affected URL, route, or repository file;
- clear reproduction steps;
- the security impact you observed;
- screenshots or a minimal proof of concept, with personal data removed; and
- a safe way to contact you for follow-up.

Use the subject line: `Security report: francinemariebautista.com`.

## Responsible testing

Please avoid privacy invasion, destructive testing, denial-of-service activity, credential attacks, social engineering, automated spam, or accessing data that does not belong to you. Stop testing and report the issue if you encounter private information.

The FMB ecosystem will assess good-faith reports, preserve relevant evidence, and coordinate a fix before public disclosure whenever possible.
